# ADR-0010 · 证据归档面归本仓（`ingest.raw` 写读面落地）

- 状态：已采纳（2026-11-12）
- 决策：本仓（数据面负责人），跨仓同步 core / ui
- 关联：ADR-0008（本 ADR **取代其决策一**）、core ADR-022（证据坐标设计原文）、`docs/db-schema.md` §9.5、`docs/TASKS.md` `DATA-INGEST-RAW`

## 背景

core `cmd/analysis/main.go` 的注释早已写明：「证据坐标改由数据服务仓的归档面提供，本进程不再注册。」设计原文（ADR-022 §5）对证据 API 的要求是：

> `GET /api/evidence/{content_hash}` → `ingest.raw` 中的唯一原始记录（不可变）。

现行消费者是 UI A-06「证据质问内嵌」：数字点击后按 `content_hash` 取回复核，接口 404 时标注「未摄取，不编造引用」。

也就是说：**归属已经指明、需求是「可查阅归档」、实现缺失**。ADR-0008 决策一把它判成「无回放消费者、挂起」，把实现缺口写进了设计；本 ADR 纠正这一点。

## 决策

1. **归属**：`ingest.raw` 的归档写面与读面都归本仓（单写者 = data 服务）。core **只保留** `GET /api/evidence/{content_hash}` 读反代（`x-served-by: data-service`），**不得**在 core 另建证据存储。
2. **写面**：`POST /api/ingest/raw`，请求 `{source, dataset, key, as_of?, payload, content_hash?}`。顺序固定为 **脱敏 → 规范化 → sha256 → 落库**；`fetched_at` 由服务端填。同 hash 同内容幂等（no-op），同 hash 异内容 500，不覆盖。
3. **读面**：`GET /api/evidence/{content_hash}` 取单条（格式非法 400，不存在 **404 `evidence_not_found`**）；`GET /api/evidence?source=&dataset=&limit=&offset=` 按 `fetched_at DESC` 列最近 N 条（`limit` 缺省 20、上限 100，越界 400）。
4. **脱敏（落库前）**：键名归一（小写、去 `-`/`_`）后命中 `token / accesstoken / refreshtoken / secret / clientsecret / password / passwd / apikey / authorization / cookie / setcookie / credential / credentials / session / sessionid / privatekey` 的值替换为 `"[REDACTED]"`；嵌套对象/数组递归。键集合与口径写在 `docs/db-schema.md` §9.5，实现与测试在 `internal/evidence`。
5. **保留期（必须有明确口径）**：默认 365 天，`EVIDENCE_RETENTION_DAYS` 覆盖；0 / 负数 / 非整数在启动期拒起。清理口径 `fetched_at < now-N 天`，schema 就绪后立即一次、此后每 24h 一次（`PurgeExpired`），不参与读面判定。
6. **不做回放**：本 ADR 只落「可查阅归档」。设计原文与 UI 契约都没有重放语义；将来若出现回放/重放消费者，另立 ADR，不在本表上顺手扩。

## 为什么推翻 ADR-0008 决策一

- 决策一的前提是「当前没有回放/审计取证需求」。但证据链消费者（UI A-06）已存在，且 core 注释早已把坐标指向 data——缺的是实现，不是需求。
- 决策一还要求「至少一个回放消费者」。本次核对设计原文后确认：**要求是可查阅归档，不是回放**。把「回放」当成重开前提，等于把归档需求误读成回放需求。
- ADR-0008 决策一的其他结论（传输多门、其余零写者表挂起）不受影响。

## 代价与已知限制

- `ingest.raw` 从「零写者表」移入有写者表；`docs/db-schema.md` §9.1/§9.2 的计数同步调整。
- 超过保留期的记录不可再查：引用会从「可查」变成 404。这是明确的运维口径（§9.5），不是缺陷；需要长期留证的部署应调大 `EVIDENCE_RETENTION_DAYS`。
- 脱敏后无法从归档取回原始敏感值（有意为之）；排障需要原始报文时，应在调用方日志侧按同一规则处理，而不是要求归档留明文。
- 单条请求体 ≤ 8 MiB；大批量原始报文不入归档，仍走作业层的有界批次。

## 验证

- `internal/httpapi/evidence_test.go`：201 / 400（坏 hash、limit 越界、hash 不符）/ 404 / 503；脱敏先于哈希（写含 `token` 的 payload，读回与哈希都不含原值）。
- `internal/store/evidence_pg_test.go`（`DATABASE_URL` 门控）：写读一致、重复写幂等、不存在 → 404、列表排序/过滤、`PurgeExpired` 只删过期。
- 破坏验证：清空脱敏键集合应红；`EVIDENCE_RETENTION_DAYS=0/-1` 应红；把不存在 id 映射成 500 应红（要求 404）。
- core 合同测试保证 `/api/evidence/{content_hash}` 在 openapi、路由表与 `x-served-by` 白名单三处一致。
