# ADR-0012 财报写面归本仓（market.stock_fundamentals）

- 状态：已采纳（2026-11-12）
- 决策：本仓（数据面负责人）
- 关联：ADR-0002（DDL 归属与 visible_at 三集合）、ADR-0004（写面幂等用内容比对）、ADR-0008 / 0009（参考数据旁路与形状收口）、`docs/db-schema.md` §1.2 / §9.1、`docs/api-schema.md` §1、`docs/dataflow.md`「参考数据」节

## 背景

多因子回测暴露数据面缺口：`value` / `quality` 两个维度按设计 fail-closed，只剩 `momentum` 撑 0.3 权重。查证结论：

- `public.stock_fundamentals` 实测 **0 行**；宽表写者 `SaveFundamental(s)` 的唯一调用方随 core `pkg/data` 退役（2026-11-11 `a96d836`）——**写点归零**，不是「读一个 schema、写另一个」的活跃错位。
- core 的 `GetFundamentalsPIT` / `GetFundamentalsPITBulk` 用裸表名 `FROM stock_fundamentals`，连接池没设 `search_path` ⇒ 读到 `public.stock_fundamentals`。
- 本仓已有 Tushare `fina_indicator` 的取数能力，但没有财报写腿。

两条路：A 本仓写 `market.stock_fundamentals`、core 改读；B 本仓跨 schema 写 `public.stock_fundamentals` 省掉 core 改动。**裁决走 A**：不为省一周破坏「每服务一个 schema」的边界——data 写 data 的 schema、core 读 data 的 schema，将来拆库能直接把 `market` 搬走。B 否掉。

## 决策

1. **表归属与形状**：本仓新增 `market.stock_fundamentals`（`internal/schema/market.go`），列形状逐字对齐 core 的 `public.stock_fundamentals`（`ts_code` / `trade_date` / `ann_date` / `end_date` / `pe` / `pb` / `ps` / `roe` / `roa` / `debt_to_equity` / `gross_margin` / `net_margin` / `revenue` / `net_profit` / `total_assets` / `total_liab`），主键 `(ts_code, trade_date)`，生成列 `available_date`，索引 `(ts_code, available_date DESC)`。`TableNames()` 由 23 增至 24，三份迁移脚本（up/down/verify）同步。
2. **传输**：`FetchFundamentalsRange(symbol, startPeriod, endPeriod)` 用 `fina_indicator` 按**报告期**区间一次拉全，不逐披露日调用（补五年历史会变成上千次请求）。解析按**响应自报 `fields`** 建列名→下标映射：源端会剔除该期全空的列（DBT-07），按固定下标会把 `roe` 写进 `pe`。源端没给的数值列落 `NULL`，**不折成 0**（0 是「真的为 0」，缺失是「源端没给」，回测的 fail-closed 依赖这个区分）。
3. **写腿**：走参考数据旁路（`job_type=fundamentals` → `ReferenceRunner.syncFundamentals` → `ReferenceWriter.UpsertFundamentals`），`ON CONFLICT (ts_code, trade_date)` upsert，新值非 NULL 才覆盖、NULL 保留旧值。**不做**内容比对整批回滚：财报会被更正/追溯调整，套点位语义会让一份更正永远写不进去。`fundamentals` 同步从 `store.writeExcludedTypes` 移出。
4. **PIT 语义**：`trade_date` = 报告期 `end_date`，`ann_date` = 真实披露日，二者都原样落库；可见性判据只认生成列 `available_date = COALESCE(ann_date, trade_date)`。三季报 9/30 截止、10/25 披露，PIT 只认 10/25。`ann_date` 缺失时退化成报告期，是已知的乐观兜底（与 core 旧表同形），不额外发明披露日。
5. **不写 `public`**：本仓不对 core 的 schema 执行任何 DDL/DML。`public.stock_fundamentals` 的退役与 core 读取切换（`GetFundamentalsPIT*` 改读 `market`，或设置 `search_path`）由 core 另立单，本仓只报「表已就绪」。
6. **部分取代**：2026-11-12「因子域 owner 回归 core」裁决中关于 `stock_fundamentals` 的归属部分；`docs/db-schema.md` §9.3 原「DDL 与写点都在 core」的结论作废。

## 代价与已知限制

- **双表并存期**：`public` 旧表在 core 改读前仍存在（0 行），期间有两份 DDL；core 切读后应显式退役旧表，否则下一个人会问「写哪张」。
- **只写不读**：core 切读前，本仓没有财报读端点，写入的正确性只能靠测试与交叉核对覆盖。
- **`fina_indicator` 根本不提供 `pe/pb/ps`**（2026-11-12 实测响应 `fields` 只有 `ts_code,ann_date,end_date,roe,roa` 等财务指标）：三列在 `market.stock_fundamentals` 中**恒为 `NULL`**。本单填的是 `roe`/`roa`/利润率等质量与成长字段，`value` 维度的估值数据仍需另接 `daily_basic`（按交易日的 `pe/pb/ps`），本单不承诺填满。
- **报告期 vs TTM**：`fina_indicator` 的 `roe` 多为**报告期累计口径**（如三季报为年初至 9/30），与 TTM 口径有差异；回测若按 TTM 使用需自行换算，本仓只存源端原值，不做二次推导。
- **更正覆盖**：后到者覆盖非 NULL 列，意味着源端若给了一个错误值、下一轮又给 `NULL`，旧错值会留下；这是「NULL 不擦除」的直接代价。需要清空某列时只能显式写 SQL（运维动作），没有 API。
- **`available_date` 生成列不可写**：写入路径不列该列；将来若要冻结可见日（例如按公告时点而非日期）需要改表，属另立单。

## 验证

- `internal/schema/schema_test.go`：`TableNames()` = 24；DDL 幂等重放（两遍不改形状）。
- `internal/transport/tushare/fundamentals_test.go`：
  - 按响应自报 `fields` 解包，列序打乱/缺列不错位；
  - `ann_date` 原样保留；缺失数值列为 `nil`（nil ≠ 0）；
  - 报告期解析失败的行跳过。
- `internal/sync/reference_test.go`：`fundamentals` 端到端（fake transport/writer），`symbols` 与报告期必填，参数不合法不发请求。
- `internal/store/reference_write_pg_test.go`：真库 `ann_date` 落库、`available_date` 跟随披露日、同参数重跑内容哈希不变、NULL 不擦已有值。
- 破坏验证：把 `ann_date` 丢掉 ⇒ 用例红；把 `nil` 折成 0 ⇒ 用例红；逐字节还原后复绿（sha256 前后一致）。
