# 0005 · 鉴权接入：kit net/http 适配 + REV-17 移植

- **状态**：已裁决（来源：裁-15，2026-10-25）
- **场景**：旧 `core:cmd/data` 已有完整 REV-17 策略表（排程管理 admin / 其余变更 trader / `POST /screen` 与 `POST /api/v1/ohlcv/bulk` any-authenticated），而新 `cmd/dataservice` **零鉴权实现**；`config/data-service.yaml` 已声明与 analysis 共用的 `AUTH_JWT_SECRET`，配置在说谎。kit `v0.1.1` 已提供 `auth/httpadapter`。
- **决策**：
  1. **机制在 kit、策略在本仓**：`internal/httpapi/auth.go` 实现 `Authorizer`，内部走 `httpadapter.Authenticate` / `Authorize`；`internal/httpapi/policy.go` 是唯一策略表。
  2. **实际路由**（`servedPolicy`）：`GET /health` = Public；`GET /datasets/resolve`、`GET /datasets/{hash}` = viewer 及以上。全部路由由同一份 `routes()` 注册并逐个包 `requireAuth`。
  3. **REV-17 逐条移植**（`legacyREV17`）：旧服务 28 条策略原样搬入本仓（条目与档位一一对应）。这些端点尚未迁入，本仓不注册它们；表作为迁移期参照，端点进来时直接挂闸，不再重新拍一次角色。
  4. **启动闸**：`/health` 公开但仍过闸（未装配 Authorizer → 503，服务端装配错误应显式暴露）；有 secret 开鉴权；无 secret + 回环 = 开放；**无 secret + 非回环 = 拒绝启动**（默认 `:8081` 全网卡，必须显式配置 secret 或声明 `AUTH_INSECURE_EXPOSURE=loopback-published`）。
- **理由**：token 校验与角色 any-of 是跨服务同一套语义，留在 kit 才不会漂移；策略是数据面业务，留在本仓才可审计。路由表与策略表同源注册 + 双向守卫，漏登即红。
- **代价 / 后果**：
  - 新增对 `github.com/ruoxizhnya/tellurion-kit v0.1.1` 的依赖（编译闭包含 gin，源码不 import gin）。
  - **默认启动行为变了**：裸 `go run ./cmd/dataservice`（`:8081` + 无 secret）现在会被启动闸拒绝；本地开发需 `-addr 127.0.0.1:8081` 或显式 `AUTH_INSECURE_EXPOSURE=loopback-published`。
  - 旧端点迁入前，REV-17 表只是参照，不产生运行时保护；真保护仍在 core `cmd/data` 的 gin 中间件。
  - core `proxyRequest` 必须透传入站 `Authorization`，否则 `POST /api/v1/ohlcv/bulk` 在网关处被数据服务 401；该腿已于 2026-10-25 落在 core。
- **替代关系**：不替代 0001–0004。旧 `cmd/data` 的 REV-17 表仍是其运行时真相；本表只是迁移目标。
