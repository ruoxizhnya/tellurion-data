# 0006 · 跨仓写入经 HTTP 投点，投影与闸门归 `internal/assembly`

- **状态**：已裁决（QT-40 H4 ②，2026-10-25，主任在两个可行分支里拍了 B）
- **场景**：core 是 `market` / `ingest` 的第二写者，用 `ON CONFLICT DO UPDATE`（后写覆盖），与本仓 ADR-0004 的「内容比对 + 异内容整批回滚」在**同一批表**上并存。工单给了两条停法：(A) core 直接改调本仓的 `store.BulkInsert`；(B) core 停掉这两条作业，把职责整体交给本仓。**实测两条都不成立**：
  - A 机械不可行 —— `internal/store` 是本仓的 internal 包，且本仓 module path `tellurion-data` 首段无点。临时模块里真编了一次，报错 `use of internal package tellurion-data/internal/store not allowed`；要绕过只能加仓外 `replace`，那是 12 仓 `AGENTS.md` 共同的禁区，也正是本仓存在的理由要被拆掉的那件事。
  - B 是**悬空而不是交接** —— 本仓没有同步作业层（无 scheduler / worker），传输实现仍在 core（ADR-0003），本仓这一轮也不许实现传输。停掉两条作业 = `capital_flow` / `top_list` 两张表不再更新，直到传输与作业层都迁进来。
- **决策**：
  1. 本仓开**唯一一条写端点** `POST /ingest/points`：只收**已归一**的点位、只开 A 集、必须有界。
  2. core 的 `capitalFlowExecutor` / `topListExecutor` 保留取数与归一（**传输的所有权不动**），把**落库那一跳**改成投点。于是 core 不再是这两张表的写者，而本仓也不因此拿到传输。
  3. 新增 `internal/assembly`，作为 `ingest.UnifiedDataPoint → store.Point` 的**唯一投影处**（ADR-0004 第 2 条预留的那个「未来的装配层」）。HTTP 投点（`Write`）与作业管线（`Pipeline`）**共用同一条写侧链**：`ValidatePoints → GatePoints → Deduplicate → 投影 → BulkInsert`。
  4. **闸门输入定死**：`visible_at` 只由该 data_type 的声明锚点推导，`ingest_time` 只由本进程注入的时钟填；这两个字段不在投送面上——出现即解码失败（`DisallowUnknownFields`），不是「忽略」。
  5. 写端点档位 = `service` + `admin`，**不跟读端点放开到 viewer/trader**。
  6. core 侧装配缺失（未配 URL / 未配 token / data-service 不可达）⇒ 作业**当场失败**，不降级回 core 的 `BulkInsert`。
- **理由**：写面归属由「谁拥有 DDL 与幂等语义」决定（ADR-0002 / 0004），不是由「谁触发作业」决定。跨仓调用做成 HTTP 是今天唯一机械可行的形态；把闸门放在落库那一侧，调用方才不能自己声明「我这批是可见的」——否则 `GatePoints` 只是装饰，而前视数据一旦入库，回测结果虚高是**不会报错**的那种坏。两条入口共用一条链，防的是「跳过 / 去重 / 闸门」的计数口径在本仓内部悄悄分叉。
- **代价 / 后果**：
  ① **这是一次真实的破坏性语义变更，作用在两表上**：`capital_flow` / `top_list` 从「后写覆盖」变成「同主键异内容 ⇒ 409 `content_conflict` + 整批回滚」。上游修正历史数值、或同一主键换源（本仓刻意比对 `source` 列），都会**响亮失败**而不是静默改写。受控修正流程**还没有**——登记为待裁（见下）。
  ② 多一跳网络与一个进程依赖：`tellurion-data` 的 `cmd/dataservice` 必须部署、可达、且调用方持 token。今天 compose 里的 `data-service` 是 core 的 `cmd/data`，本仓这个进程**尚未上部署清单** ⇒ 装配不配好，这两条作业就是失败的（这是设定，不是待修的 bug）。
  ③ 有界批次（10000 点 / 8 MiB）把「一次作业」切成多次请求：跨请求失败时**已落的那片不回滚**，作业层原本的「整池一次」原子性不再覆盖整池。读 `sync_jobs.error_message` 时要按分片理解。
  ④ 写端点上开 `admin` 是**权宜**：core 的 `pkg/auth` 角色集今天仍是 {viewer, trader, admin}，签不出 `service`（QT-71 未落）。QT-71 落地后应收紧成只 `service`，那是档位 breaking，要追加本条或另立一条，不许悄悄改表。
  ⑤ **今天没有被真实 PG 端到端跑过**：写端点的腿是「真装配 + 真 `store.Writer` + 无库 Exec 替身」与替身 sink；真 SQL 作用在真表上只有 `internal/store` 的 `DATABASE_URL`-gated 套件。另有一条现实依赖：生产 `public.*` 表上 `visible_at` 列是否存在，取决于本仓启动迁移有没有跑过（core 的内联 DDL **没有**这一列）。
  ⑥ **第二写者没有整体消灭**：core 仍写 `ohlcv_daily_qfq` / `sectors` / `stock_sector_map`（无前缀，落 `public`），另有 `market.index_daily`、`ingest.raw` 两处带前缀写点。物理 `SET SCHEMA` 的前置因此从「停两个 executor」改成「core 的 A 集写点全部归一或停写」——见 `docs/db-schema.md` §1.5 的实测口径。
- **待裁（本条不接受完就算完）**：
  1. 同主键异内容的**受控修正流程**：409 之后由谁、经什么口子改写历史行。（ADR-0004 代价 ④ 早已登记，本条把它变成**运维会真撞到的**问题。）
  2. 写端点档位收紧为只 `service` 的时点（绑 QT-71）。
- **替代关系**：补充 0004（那句「投影在装配层完成」由此落地）与 0003（传输仍留 core），不取代它们。core 侧的对应记录在 `tellurion:docs/TASKS.md` 的 QT-40。
