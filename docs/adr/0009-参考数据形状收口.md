# ADR-0009 参考数据形状收口：交易日历单交易所、退市日落库

- 状态：已采纳（2026-11-11）
- 关联：QT-40、ADR-0008、`docs/db-schema.md` §9.1、`docs/dataflow.md` §2「参考数据」
- 范围：`market.trading_calendar`、`market.stocks` 的存储形状；不改 DTO、不改点位管线

## 背景

ADR-0008 把参考数据（`stocks` / `trading_calendar`）接进了本仓写面，但留了两条已知限制：日历主键只有 `trade_date`（多交易所会覆盖 `exchange`），`stocks` 不落 `delist_date`（退市只能靠 `status` 表达）。本 ADR 判断这两条是否真实风险，并给出收口方式。

## 决策一：`trading_calendar` 按「单一 A 股交易日历」写死，不改主键

### 事实与证据

- 唯一读方 `store.TradingDays` 的 SQL 只选 `trade_date`，不筛也不返回 `exchange`；`GET /api/v1/trading/calendar` 的响应是 `[]time.Time`，没有交易所维度。
- `ReferenceRunner` 的日历作业默认 `exchange=SSE`；2026-11-11 线上核对 `trade_cal` 返回的 `exchange` 恒等于请求值。
- A 股各交易所（SSE / SZSE / BSE）的交易日一致：同一批法定休市，没有「上交所开市、深交所休市」的日期。

### 选项与代价

- **A · 改复合主键 `(exchange, trade_date)`**：要改 DDL、迁移既有行、改读方（去重或按交易所筛选）、改接口响应形状与 `calendar_hash` 输入，代价落在多个仓；服务的是一个**不存在**的消费场景。
- **B · 保持主键，写死单交易所假设**：写侧拒混批 + DDL `CHECK`（新库）+ 文档声明；读方与契约零改动。

### 决定

选 **B**。`trading_calendar` 是「一张 A 股日历」，`exchange` 列只是**最近一次写入来源**（provenance），不是维度。

落地：

- `store.ReferenceWriter.UpsertTradingDays` 在开事务前检查批次；混入多个交易所返回 `ErrMixedTradingExchanges`，一条 SQL 都不发（跨作业先后写不同交易所仍允许，因为值相同）。
- DDL 把 `exchange` 收紧为 `NOT NULL DEFAULT 'SSE'` + `CHECK (exchange IN ('SSE','SZSE','BSE'))`。**只对新建表生效**：本仓没有通用 `ALTER` 迁移，既有库靠写侧守卫。
- `docs/db-schema.md` §9.1 明示「单交易日历；`exchange` 仅 provenance」。

### 后果

- 误用「按交易所分片并发写」会在作业层响亮失败，而不是静默互相覆盖。
- 读方不需要去重，接口形状不变。
- 将来真要分交易所日历时，读方必须先能表达交易所维度。

### 重开条件

出现按交易所区分的消费者（响应形状或 `calendar_hash` 需要 `exchange` 维度）时，另立单：改主键为 `(exchange, trade_date)`、迁移既有行、改读方与契约响应，并补跨交易所差异的线上证据。
