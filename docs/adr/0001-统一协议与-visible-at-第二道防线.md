# 0001 · 统一协议与 visible-at 第二道防线

- **状态**：已裁决（来源：ADR-D19 / data-service-contract-and-ownership.md §2）
- **场景**：前视有两个来源：策略主动 `get_bar(t_offset>0)`，以及**数据本身泄漏**（拿报告期截止日当可见时间、用后复权价格）。第一道防线（沙箱 trap）只能挡前者；后者一旦进了库，回测跑出来就是"漂亮但错的曲线"，且没有任何报错。
- **决策**：① 所有入库数据必须带 `visible_at`，由 connector 声明、归一化层填实、aggregator 强制过滤（`visible_at <= current_bar_time`）；② 协议七要素（标的/时间/频率/行情/公司行为/质量/内容寻址）冻结进 contracts；③ 内容寻址 `dataset_snapshot_hash` 作为可复现锚点。
- **理由**：第二道防线比第一道更根本：它防的是"数据本身带前视"。把它做成协议的必填项，等于让前视数据**无法入库**，而不是靠每个策略自觉。
- **代价 / 后果**：① 每个 connector 都要认真声明时间语义，漏了会被拒收（工作量真实存在）；② 一些源没有披露日字段，需要额外补（如财报用公告日期）；③ `visible_at` 让"取最新数据"变麻烦 —— 这是有意的。
- **替代关系**：无（本仓首条）
