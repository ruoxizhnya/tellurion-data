# 0007 · 传输与同步调度自持（推翻 0003 的「传输留在 core」）

- **状态**：已裁决（2026-11-10，主任裁决 B）
- **场景**：
  - ADR-0003 定的是「connector 搬入本仓，传输实现以窄 port 留在 core，本仓只按 `Transports` 注入」。这条在 2026-10-25 之前是对的：core 的 `pkg/data` 同时持有传输与同步执行器，本仓只负责归一、闸门、落库。
  - 2026-11-08 core 退役单 `a96d836`（`SVC-CORE-DATA-RETIRE`）把 `pkg/data/**`（91 个文件，含 `tushare.go`、`source/{tushare,mootdx,eastmoney}_adapter.go`）与 `cmd/data/**` 整目录删掉。实测 core 非测试代码已无 Tushare / Mootdx 传输类型、无 `/ingest/points` 调用方。
  - 本仓因此变成「声明齐全、传输为零」：`internal/assembly` 用 `ingest.Transports{}` 全零注册，`assembly.Pipeline` 零生产调用方。**没有任何进程抓行情或跑同步**——读面靠 G3 的 7 条兼容端点供数，写面只剩 `POST /ingest/points` 等人投点。
  - 两条既有口径正面对撞：跨仓派工单的禁区写「不许在本仓实现传输」，而 core 退役单把传输删了。⇒ 二选一，主任裁 **B：改禁区，本仓自持传输与调度**。
- **决策**：
  1. **传输归本仓**：`internal/transport/tushare` 实现 `ingest.TushareTransport` 的 10 个方法（stocks / daily OHLCV qfq / fundamentals / daily_basic / moneyflow 四档 / 宏观 9 指标）。窄接口形状不变，`internal/ingest` 仍只认接口、不 import 具体传输（依赖方向：`transport → ingest`，反向禁止）。
  2. **调度归本仓**：`internal/sync`（package `syncjob`）自持 `ingest.sync_jobs` 队列、`ingest.sync_schedules` 排程、进程内 Worker（2s 轮询 + `FOR UPDATE SKIP LOCKED` 领取）与 Scheduler（30s 扫 due，自研 5 段 cron，无第三方库）。作业的 `job_type` 就是 data_type，不设第二套命名。
  3. **执行链单源**：Worker 调 `assembly.Pipeline`（`Registry.Fetch → Normalize → ValidatePoints → GatePoints → Deduplicate → BulkInsert`），与 `POST /ingest/points` **共用同一条链**，不另造第二套写面。
  4. **HTTP 作业层**：11 条端点（`POST/GET /api/sync/jobs`、`{id}`、`cancel`、`retry`；`GET/POST/PUT/DELETE /api/sync/schedules`、`toggle`、`run`），鉴权档位按 REV-17 逐条移植（排程管理 admin、其余变更 trader|admin、读 service|viewer|trader|admin）。
  5. **进程装配**：`cmd/dataservice` 在 `TUSHARE_TOKEN` 非空时装真传输；否则传输缺失、作业在行上响亮失败（`all adapters for <type> are disabled`），**不静默写 0 行**。worker / scheduler 在 schema 就绪后才启动（降级启动不灌日志）。
- **理由**：
  - **A（core 恢复传输 + 执行器）被否**：等于把刚删的 91 个文件写回来，且与本仓「消灭第二写者」（X1d）反向——core 一旦重新持有写面，`market` / `ingest` 的 owner 又变成两处。
  - **B 的最小代价**：传输与调度都是「本仓数据面的入口」，放在本仓后，DDL owner、写面 owner、取数执行者三者同位，`SET SCHEMA` 迁移才可能真正消灭第二写者。
  - **不引第三方队列 / cron 库**：单人自托管下多一个守护进程就是多一个运维面；`SKIP LOCKED` + 进程内 worker 已够用，失败可在同一进程重试。
- **代价 / 后果**：
  - 本仓生产进程从此有出网行为（Tushare HTTP）。限额 200 次/分钟在 `internal/transport/tushare` 内自限；`shibor_lpr` 限 1 次/小时，`LPR_1Y`/`LPR_5Y` 必须共用一次请求（已在实现里保证）。
  - **`ingest.raw` 原始归档没有搬**（core 旧传输顺手写证据链，本仓窄接口无归档 sink）⇒ 今天生产取数**不留 raw**。这是已知缺口，属后续单。
  - **只有 Tushare 一门是通的**：Mootdx 接口仍为空实现、东财 / Juchao / Xueqiu / Alpha Vantage / Yahoo 传输未搬。`ohlcv_daily` 链里 mootdx 恒 disabled，A 股日线只有 Tushare 一条腿。
  - worker **不自动重试**：失败即终态（`failed`），重排是显式 `POST /api/sync/jobs/{id}/retry`。自动重试会让「数据质量差」被静默掩盖。
  - 机械检查：`TestRouteTableEqualsServedPolicy`（23 条路由 ≡ 策略表）、`TestLegacyREV17DecisionsMatchOldService`（新旧角色结论一致）、`TestComposeRootWiresTheWriteFace`（装配链 9 段）、`TestPGStoreFinishJobWritesTerminalState`（真库终态可写；无 `DATABASE_URL` 即 skip）。
- **替代关系**：替代 [0003](0003-connector搬入本仓传输以窄-port-留在-core.md) 的**传输节**（「传输以窄 port 留在 core」）。ADR-0003 的 connector 声明与窄接口部分**继续有效**；本 ADR 只推翻「实现留在 core」这一半。0003 不删、状态改为「部分被 0007 替代」。
